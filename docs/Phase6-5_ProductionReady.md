## 1. チャンネル更新（新着だけ取る）

### 仕組み

```
IIncrementalCatalogImporter.ImportNew(input, boundary)
                                          ↑
                          CatalogImportBoundary
                            ├ StopAtId  … 前回いちばん新しかった ID
                            └ KnownIds  … いまカタログにある ID 全部
```

チャンネルもプレイリストも**新しい順**に返ってくるので、
**先頭 50 件だけ**見て、知っている ID を落とせば新着が残ります。
400 件のチャンネルで**取得が 8 回 → 1 回**になります。

**取りこぼしは黙りません。** 50 件が全部新しかった場合は
「まだ先にあるかもしれません。追加してからもう一度押してください」と出ます。

### なぜ `ICatalogImporter` を増やさなかったか

増やすと **CSV も JSON も、使わないメソッドを書かされます**。
別の口（`IIncrementalCatalogImporter`）に分けたので、

- 差分が取れる取り込み元（YouTube）→ 両方を実装
- 差分の意味が無い取り込み元（CSV）→ `ICatalogImporter` だけ

となり、**Builder からはどちらも同じように見えます**。
窓は `importer is IIncrementalCatalogImporter` を見てボタンを出し分けるだけです。

### 覚えている場所

`CatalogSubscription` — 取り込み元 / 入力 / 表示名 / 種類 / 最終取得日時 / 最後の ID / 累計件数。
**YouTube 固有のものは 1 つもありません。**

保存先は **`Catalog.asset` の横の JSON**（後述）。**ワールドには入りません。**

> **見張っていなくても「新着だけ」は使えます。** 前回の目印が無くても、
> いま持っているカタログの ID が目印になるからです。

## 3. Catalog と VRCUrl の同期チェック

`CatalogUrlTableBridge.CompareWithScene(asset)`

シーンの `UdonMediaCatalog.Ids` を**反射で読み返して**、アセットの ID 列と突き合わせます。

```
⚠ シーンの VRCUrl がカタログと違います。「③ VRCUrl へ焼く」を押してください。
    ワールドにまだ無い: 12 件 (abc123, def456, ghi789 ほか)
    消したのに残っている: 2 件 (old111, old222)          [いま焼く]
```

- **件数だけでは見ません。** それだと「1 件消して 1 件足した」を見逃します
- 中身が同じで並びだけ違う場合も「並びが違います」と出ます
  （カタログの並び = ワールドの「すべての曲」の並びなので）
- 窓の一番上に出て、**そこから直接焼けます**
- 未保存なら「先に保存してください」に変わります
- 調べ直しは **2 秒に 1 回まで**（シーン全体を反射で読むので毎フレームは重い）

これは Phase6-3 からの積み残しでした。保存しただけでは反映されず、
**焼き忘れても何も言われなかった**のがいちばん危ない状態でした。

## 4. 一括編集

`CatalogBulkEdit`（純粋 C#）

| できること | 備考 |
|---|---|
| ジャンルを入れる | |
| チャンネル（作者）を入れる | |
| タグを足す | **すでに付いているものには足しません**（関連の点数が二重に入るため） |
| タグを外す | |
| 種別を変える | |
| 関連を作り直す | **近さは一覧の全部から探し、書き込むのは選んだものだけ** |

**チェックは位置ではなく ID で覚えます。** 並べ替えても絞り込んでも、
**選んだものが入れ替わりません**。

**何件変わったかを必ず返します。** 出さないと「押したのに何も起きない」のか
「もともと同じだった」のか分かりません。

1. 絞り込みで対象を出す → **「表示中を全部チェック」**
2. 「まとめて直す」タブでジャンルを打って **「入れる」**

まとまり表示なら、チャンネルの見出しの **「全部☑」** でも選べます。

## 5. 並び替え

`CatalogSortOrder`（純粋 C#）— 手動順 / 公開日 / 見出し / チャンネル / 再生時間、昇順・降順。

**データは並べ替えません。** 返すのは**元の位置の番号**だけです。

1. **手動順に戻せる。** 並べ替えて保存すると、自分で決めた並びは二度と戻りません
2. **再生側の並びが勝手に変わらない。** カタログの並びは
   ワールドの「すべての曲」の並びそのものです

`CatalogItemFilter` と同じ約束なので、**絞り込みと並べ替えはそのまま重ねられます**。

- 同じ値なら**元の位置の順**（何度やっても同じ並び）
- 公開日が空のものは**必ず後ろ**
- チャンネル順は**同じチャンネルの中を見出し順**に
- 並べ替え中は ▲▼ の移動を止めます（見えている隣と本当の隣が違うため）

公開日は `CatalogDraftItem.PublishedAt` に入ります（YouTube の `publishedAt`）。

## 7. 直した不具合（Phase6-4 まで）

**保存して読み直すと、サムネイルと出どころが消えていました。**

`MediaItem` は**再生に要るものしか持ちません**。
サムネイル URL・公開日・出どころは通り道で落ちていました。

**直し方**：`Catalog.asset` の横に `Catalog.builder.json` を置き、
再生に要らない情報と見張り先をそこに書きます（`CatalogSidecar` / `CatalogSidecarIO`）。

```
MediaCatalog.asset          ← ワールドに乗る。再生に要るものだけ
MediaCatalog.builder.json   ← 乗らない。サムネイル・公開日・出どころ・見張り先
```

- **ID で突き合わせる**ので、並べ替えても順番が変わっても正しく戻ります
- 中身が空なら**書かずに消します**（手入力だけのカタログにファイルを増やさない）
- 壊れていても**編集は続けられます**（読めなければ空として扱う）
- テキストなので **git の差分が読めます**

## 11. Phase7（同期システム）へ移る前に残る課題

### 先に片づけたほうがよいもの

1. **消えた動画の検出**
   YouTube で削除・非公開になった動画は、カタログに**残ったまま**です。
   ワールドでそれを選ぶと再生に失敗します（Phase3-4 の回復処理で次へ飛びますが、
   **一覧には出続けます**）。「まとめて確認して印を付ける」が要ります。

2. **50 件を超える新着**
   `ImportNew` は 1 ページ（50 件）しか見ません。
   半年ぶりに更新すると足りず、いまは「もう一度押してください」で凌いでいます。
   `IYouTubeClient` にページ送りを足せば 1 回で済みます。

3. **実機での確認がまだ**
   Phase5-4（同期）・Phase5-5・3 秒問題・Phase6-1〜6-5 の**実機テスト結果を伺えていません**。
   Phase7 は同期を作り込む段なので、**Phase5-4 が実機で動いていることの確認は
   その前提**になります。

### Phase7 と関わるもの

4. **カタログが大きいときの同期**
   `UdonSyncCoordinator` が同期するのは 5 つの値だけなので件数には強いはずですが、
   **200 件を超えるカタログで実際に確かめていません**。

5. **カタログの差し替え**
   ワールドを再アップロードせずにカタログを更新する道は今のところありません
   （`VRCUrl` を実行時に作れないという Phase1-2 からの制約）。
   Phase7 で「複数カタログの切り替え」を考えるなら、ここが効いてきます。

### あると便利なもの

6. サムネイルをワールド内パネルにも出す（容量の設計が要ります）
7. JSON / CSV Importer（口は空いているので、実装 1 つ書くだけです）
8. 一覧の頭出し（「あ行」ジャンプ）
9. カタログ同士の差分表示
