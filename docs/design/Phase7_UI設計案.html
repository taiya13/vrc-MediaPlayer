02

直し方の方針

Spotify・YouTube Music・Steam に共通しているのは 「いま聴いているものを大きく、探すものはカードで、設定は奥へ」の 3 点です。 VRChat 自体の UI も、押せるものが大きく少ないところが同じです。 これを VR の制約（腕の届く距離・2 m 先の可読性）に合わせて持ち込みます。

一度に見せる一覧は 1 本だけ

「すべての曲 / おすすめ / 再生予定」をタブで切り替えます。同時に見える行が 13 → 5 になり、1 行あたりに使える面積が 2 倍以上になります。

タブは いま何件あるかも出します（「再生予定 3」）。切り替えないと分からない、を防ぎます。

再生中を、パネルの主役にする

左半分をまるごと使い、73 × 41 cm のサムネイルを置きます。2 m 離れても何が鳴っているか一目で分かります。曲名は 46 px（6 cm）で、一覧の 2 倍近い大きさです。

大きいボタンは 3 つだけ

前へ・再生 / 一時停止・次へ。この 3 つが操作の 9 割です。停止と「予定を空に」は「…」の中へ移します。音量は −／＋ の 2 つに減らして 1 行に収めます。

行にサムネイルと 2 段組を入れる

1 行 112 px（14.6 cm）。左に 160 × 90 の絵、右上に曲名、右下にチャンネルとジャンル。絵とジャンルの色で、読まずに見分けられます。

おすすめは「理由」を添える

ただ並べるのをやめ、「○○ と同じチャンネル」「同じ Vocaloid」のように、なぜ出ているかを 1 行で書きます。Phase6-4 の関連生成がすでにこの情報を持っています。

余白を 3.6 cm → 5.7 cm に

外周 44 px、区切り 36 px、行間 10 px。罫線を減らして余白で区切ります。開発ツールらしさの大半は、詰まった罫線から来ています。

VR の制約は守ります

押せるものはすべて 4.5 cm 以上（Phase5-5 で決めた ComfortableTouchMeters）。 パネルは 1.82 m 幅のまま — これ以上広げると首を振らないと端が見えません。 レイキャストが通らない実機に備えて、uGUI と「使う」の両対応も維持します。

06

決めていただきたいこと — サムネイルをどう出すか

ここだけ判断が要ります

いまサムネイルはワールドに入っていません。 Phase6-5 で「Editor だけで持ち、ワールドの容量を増やさない」と決めたためです。 上の案は絵が主役なので、絵をワールドへ持ち込む方法を決めないと成立しません。 3 つの道があります。

A. 編集時に焼き込む

おすすめ +3.6 MB / 200 曲

VRCUrl と同じやり方です。Catalog Builder がすでに絵を持っているので、 256 × 144 に縮めて Texture2D の配列に焼きます。

  • 確実に出ます。通信も待ち時間もありません
  • すでにある「③ VRCUrl へ焼く」に相乗りするだけ
  • 200 曲で約 3.6 MB（DXT1 圧縮）。ワールドの上限には十分収まります
  • 曲を足したら焼き直しが要ります（URL と同じなので手間は増えません）

B. 実行時にダウンロードする

容量 0
  • ワールドの容量は増えません
  • 画像の URL も VRCUrl なので、結局 200 本ぶん焼く必要があります（手間は A と変わらない）
  • 読み込みに数秒かかり、失敗することもあります
  • ワールドに入った直後は絵が出そろいません

C. 絵をあきらめる

容量 0・作業 0
  • 絵の代わりにジャンルの色（Phase6-6 の 23 ジャンル）で塗り分けます
  • レイアウトはそのまま使えます。絵の枠が色の面になるだけです
  • 「見ただけで分かる」度合いは A に届きません

A をおすすめします。 いちばんの目的が「曲を探しやすくする」ことなので、絵は効果が大きく、 3.6 MB は VRChat のワールド容量（PC 版で数百 MB）から見れば小さい負担です。 C でも上のレイアウトはそのまま作れますので、 迷う場合は C で作って、あとから A を足すこともできます。

責務の分け方は 1 つも動かしません。 PlayerSession / BackendAdapter / Queue / Recommendation / VideoBackend はそのままです。 VRCUrl を知るのも VideoBackend 層だけのままです。

変えるのは 「どう並べるか」を決めている UdonMediaPanelBuilder と、 表示だけを持つ 5 つのクラスです。 判断ロジック（PlaybackModel / ListScrollModel）にも触りません。 既存のパネルは作り直しになりますが、 Core を挿し直すだけで動きます。

お返事をいただきたいのは 2 つです

  • ① この画面構成で進めてよいか。 直したいところ（行数・ボタンの並び・タブの名前など）があれば教えてください。
  • ② サムネイルは A / B / C のどれにするか。 決まらない場合は C（色分け）で作り始めて、あとから A を足すのが安全です。

なお、Phase5-4（同期）以降の実機での確認結果をまだ伺えていません。 Phase7 はパネルを作り直す段なので、いまのパネルが実機で問題なく押せているかだけ、 先に教えていただけると安心して進められます。
